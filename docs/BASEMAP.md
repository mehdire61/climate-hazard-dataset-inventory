# Global reference map

The inventory uses OpenStreetMap-based OpenMapTiles vectors distributed by OpenFreeMap. The reference map gives practitioners the same cartography for a river gauge, inland lake, coastal buoy, island or international study area. Water is blue. Administrative areas have thin outlines, and the selected project footprint has a light teal fill. [OpenStreetMap uses in industry and government](https://welcome.openstreetmap.org/about-osm-community/consumers/) · [OpenFreeMap service](https://openfreemap.org/)

Choosing **Online detail** enables the provider connection. When the map needs detail beyond the bundled overview, it reads the provider’s current TileJSON and requests the tiles for the visible area. Project files and station identifiers stay out of these requests. The local overview uses a dated extraction from the provider’s published global PMTiles archive and loads regions as needed. Service failure leaves the overview and project controls available. OpenFreeMap offers the public service on a best-effort basis and publishes archives for self-hosting. [Source and downloads](https://github.com/hyperknot/openfreemap) · [Service terms](https://openfreemap.org/tos/) · [OpenMapTiles schema](https://openmaptiles.org/schema/)

The map supports geographic orientation and station selection. Shoreline detail depends on zoom, data vintage and local mapping. Coastal engineering work can require a separately sourced shoreline with a defined tidal datum and survey date. Coverage screening, station eligibility and project exports use the submitted coordinates and project geometry. [NOAA shoreline interpretation](https://nauticalcharts.noaa.gov/publications/docs/us-chart-1/ChartNo1.pdf)

For static hosting, deploy `index.html` together with `data/map-tiles/` in the same directory structure. The HTML embeds the world overview. Regional tiles load on demand from the local folder. Map attribution, source vintage and archive checksums are included in `data/offline-basemap-LICENSE.txt` and `data/offline-basemap-source.json`.

The ordinary map uses Web Mercator, which preserves local angles. The search ring follows points at the requested spherical distance around the project. For local point searches beyond the tiled latitude range, an azimuthal equidistant view preserves distance from the center in every direction. Broader searches and polar area boundaries use a latitude–longitude overview. In the polar view, coordinate lines, a scale and a pole reference help orient the project. [Leaflet coordinate reference systems](https://leafletjs.com/reference.html#crs) · [Azimuthal equidistant projection](https://proj.org/en/stable/operations/projections/aeqd.html)
